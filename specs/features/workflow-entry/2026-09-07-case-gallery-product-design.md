# LobsterAI 首页案例入口 PRD · 简化修订版

版本：v0.3 · 更新日期：2026-09-07 · 状态：设计评审稿，应用代码未实施。

本稿根据用户提供的参考图重做页面层级，替代 2026-09-06 版首页画廊方案。推荐方案是：**首页以原输入框为主体，下方只保留一条分类导航和四个封面案例；完整目录、岗位筛选和五页案例放进「浏览全部」。**

## 1. 这次要解决的问题

上一版把分类、岗位、数量、分页、材料说明和使用按钮同时摆在首页，用户需要先读一块复杂目录。参考图的优点是主次明确：先看输入区，再看分类与成品封面，更多内容从「浏览全部」进入。

这次主要调整信息层级和页面密度。保留有内容的图文封面，减少边框、底色、标签和重复操作；不把图片统一改成灰色，也不复制参考图里的付费标识、积分和未验证的功能分类。

| 项目 | 本版定稿 |
|---|---|
| 首页主体 | 欢迎语与原输入框居中；案例入口在下方，视觉权重低于输入框 |
| 首页分类 | 精选、写作、表格、幻灯片、网页；选中项用浅灰底，其余为普通文字 |
| 首页案例 | 默认四个、宽窗口一行四列；只展示封面、简短标题、成果类型 |
| 深入查找 | 右侧「浏览全部」进入同一应用中的案例目录；在这里显示岗位筛选、数量与分页 |
| 点击案例 | 在原输入框中加入轻量模板提示；用户添加材料后用原发送动作开始 |
| 调整要求 | 默认收起在「更多要求」中；必要信息仍在材料提示中直接说明 |

## 2. 首页布局与视觉规格

首页主内容按以下顺序排列：应用现有页头 → 欢迎语 → 原输入框 → 留白 → 分类导航与「浏览全部」→ 四个案例。沿用既有侧栏、顶部账号入口和配置控件，不做全局信息架构重组。

**整体：** 浅色为白色/近白色工作区，深色遵循现有主题；正文深灰、辅助说明中灰。品牌强调色仅沿用已有主要操作，不给每个模块加彩色容器。

**输入区：** 中心对齐，最大宽度约 680–760px；案例区可更宽，参考 960–1120px。输入框保持浅边框与轻微阴影。欢迎语与输入框之间约 28–40px，输入框与案例分类之间约 48–64px。

**留白：** 在常见桌面窗口中，欢迎语、输入框、案例分类和第一排封面应可见。矮窗口先缩减顶部留白，不通过缩小文字或裁掉案例来硬塞内容。原型提供「舒展 / 紧凑」评审选项，产品不增加对应设置开关。

**案例区：** 不再叠加「找一个与你工作有关的案例」大标题和长说明；分类行本身就是入口。「精选」表示人工编排，首版没有个性化推荐能力，也不用「为你推荐」暗示已经识别用户岗位。

**分类：** 精选 / 写作 / 表格 / 幻灯片 / 网页。分类帮助识别交付形式，底层仍保留 caseId、场景和岗位标签；它不是数据分析中的需求分类或功能喜爱度榜。

**卡片：** 整张可点击，无外层卡框和底部「使用案例」按钮。封面建议统一 16:10、圆角约 12–16px；标题在图下，最多两行；下一行只显示图标与 Word、Excel、PPT、网页等成果类型。键盘焦点清晰，交互不依赖悬浮。输入要求与岗位信息移到点选后或目录筛选中。

**封面：** 颜色和细节集中在封面内部。优先从检查过的示例成品渲染，分别能认出文档、表格、幻灯片或网页；不要叠加格式角标、岗位标签、热门标签和宣传大字。封面失败时使用统一的格式占位和标题，卡片仍可选择。

**响应式：** 根据案例区可用宽度布局：约 840px 及以上四列，480–839px 两列，更窄时单列。分类可换行，「浏览全部」始终可见；首版不自动轮播、不横向劫持滚动。

## 3. 首页发现与「浏览全部」

### 首页只负责帮助开始

默认精选：周报整理、多表合并、季度汇报 PPT、活动邀请页，覆盖四种容易认出的交付形式。选择依据是已有模板基础和首屏辨识度，属于设计假设，不是研究已证明的热度排序。

切换分类后，就地展示该类最多四个案例。首页不显示「20 个案例」「1/5」、岗位下拉框、搜索框和多行说明。原输入草稿与附件不受分类切换影响。

### 完整目录承接四五页的浏览需求

点击「浏览全部」打开同一应用内容区内的案例目录，带清楚的「返回首页」；不新增全局导航项。沿用首页分类，并提供一个可选岗位筛选。默认 20 个候选、每页 4 个、共 5 页；筛选后页数按结果重算。

从首页某分类进入目录时保留该分类；从精选进入时展示全部。目录切分类/岗位回到第 1 页，数量与当前页在这里显示。「通用」案例匹配各岗位；岗位与成果类型取交集。空结果给「清除筛选」，上一页/下一页在边界禁用。

选择案例后返回原首页输入区；在模板提示中可「继续浏览」，恢复选中前的目录分类、岗位与页码。返回首页本身也不丢失草稿、附件和已选案例。

## 4. 点选之后，输入框只增加一层轻提示

空草稿选择「周报整理」后，在原输入框内依次显示：

1. 一行当前案例名与关闭按钮，使用普通文字/细分隔线，不铺整块品牌色底。
2. 材料提示：「粘贴本周要点，或添加记录文件」；旁边提供弱化的「试用示例」文字入口。
3. 原正文区填入简短、可编辑的任务请求；原附件入口、助手、模型与发送操作继续使用。
4. 可选「更多要求」默认收起；展开后最多一个有默认值的选项，如「给谁看：主管 / 团队」。

点击卡片不会自动发送或创建任务。取消案例只移除案例提示与选项，不删除正文或附件；用户原有文字必须保留。更换案例时，仅当正文为空或仍等于未改动的自动文案时才替换自动文案。

有会影响执行的默认选项时，选项值必须可见：收起态显示例如「更多要求 · 向主管汇报」。实际提交组合当前案例目标、选项、附件引用与用户补充，不把重要参数藏在界面外。素材已存在但可能不适配新案例时给简短提示，由用户决定是否保留。

「试用示例」仅选入当前案例的合成/匿名素材，附件明确标注「示例」，仍由用户发送。已有个人文件或粘贴材料时不自动混入示例，不覆盖原内容；用户主动移除后再试用。只填写了默认任务请求而没有实际材料时，就地提示添加材料或使用示例；用户修改请求用于咨询时允许直接发送，不做文件数量或字数硬门槛。

发送后走现有任务与权限链路。真实产物由现有文件卡片承接；本轮保留此前对 DOCX/XLSX 的「继续修改」建议，但它不影响首页布局，也不是案例画廊上线的前置依赖。不得以模板或演示图证明文件已生成、核对完成或内容无损。

候选内容沿用前版 20 个：16 个映射现有模板，4 个补充文档/表格模板候选。首页精选顺序单独配置；目录顺序不代表用户偏好。以下材料与产物均需真实执行验收后才能对用户开放。

## 6. 实施边界与验收

首页案例区和完整目录复用同一份案例配置、筛选逻辑与卡片；现有快捷模板区域作为替换位置。模板选择继续接到原输入框/附件/任务提交链路，文案通过现有 zh/en 配置加载。仅做局部组件拆分，不以此重构大型 CoworkView 或 OpenClaw。

| 验收项 | 必须满足 |
|---|---|
| 首页清晰度 | 宽窗口仅一排四个案例；首屏没有岗位筛选、数量、分页和重复使用按钮；主视觉为欢迎语与输入框 |
| 完整浏览 | 目录可浏览全部候选；第 5 页、分类/岗位组合、空结果与返回路径均明确 |
| 模板准备 | 点选不执行；材料提示即刻可见；默认要求可见但表单收起；切换/关闭不丢草稿或附件 |
| 示例边界 | 示例材料标注明确；与已有个人文件/文本不自动混合；个人材料任务和示例任务分开统计 |
| 文件结果 | 真实输出能打开且与示例类型一致；数字、来源、重复项和未改区域按具体任务核对；不依赖模型自述 |
| 可访问性 | 键盘可切分类、选案例、进入/退出目录；封面失败仍可操作；320px 到桌面宽度无文字、按钮遮挡 |

改动优先级：先完成首页展示与模板轻提示，再接完整目录；案例内容随真实验收扩充。此前的结果续改可独立排期，不把它、外部系统连接或定时执行捆成一次大改版。

## 7. 如何判断新版有效

比较旧模板区与简化案例入口，按稳定账号固定分组，保持模型、核心任务能力与其他引导一致。不要同时把首页、目录、任务引擎全部替换后将变化归因于封面。

- 发现：分别记录首页案例实际曝光、目录进入、目录案例曝光与案例选择；用 caseId、入口、分类、页码和版本关联，不把目录进入当作完成。
- 开始：比较首页曝光账号中，24 小时内提交个人材料案例任务的比例；示例体验单列，观察窗口未满的账号不纳入比较。
- 完成：用实际产物打开与人工任务验收分别观察，不把点击发送或打开文件直接称为成功；访谈核对用户是否采用。
- 使用成本：观察不借助口头指导能否选中合适案例、找到材料入口、返回原页；与对照组比较所需步骤和时间。

最新研究的样本与分类只能支持围绕材料、成品与修改设计入口，不能证明本版风格必然提升留存。先恢复已有模板与产物字段的查询/关联能力，再最小补齐曝光和入口标识；不收集文件内容、文件路径或用户输入原文。
