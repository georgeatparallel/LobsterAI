# LobsterAI 小改版产品设计稿

> 后续首页入口已扩展为 [案例画廊与交互模板](./2026-09-06-case-gallery-product-design.md)。首页发现与选择以新稿为准；本文的材料接收和文件续改规则继续作为基础。

日期：2026-09-06。状态：本轮推荐定稿，供设计和研发评审；尚未实施应用代码。

本稿替代上一轮大范围方案。范围锁定为现有首页和会话内的两处增强，先在已有的「周报生成」「多表合并整理」模板验证。页面结构、四类模板、任务历史、作品预览、模型与助手选择继续沿用现状。

## 1. 最终方案与改动范围

| 位置 | 现有体验 | 本次改动 |
|---|---|---|
| 首页模板 → 原输入框 | 点击模板，填入一段提示词，然后聚焦输入框 | 两个试点模板改用简短请求；输入框内增加一条「材料提示 + 添加材料」，明确先放什么。模板卡片的描述同时写清输入和结果 |
| 原会话中的文件卡片 | 点击预览，或通过「打开方式」回到本机软件 | 给本会话生成、带有效本地路径的 DOCX/XLSX 文件增加「继续修改」；点击后在原输入框引用这份文件，用户补充要求后再发送 |

整个改动只有一条准备提示和一个续改动作。不新增页面、主导航、作品库、流程库、工作流编辑器或桌面悬浮入口；也不引入作品版本数据库、通用检查引擎和新运行时。这些均退出本轮范围。

「简单耦合」落在已有的文件来回流转上：用户继续在 Excel、Word 或原业务软件准备材料，拖入 LobsterAI 处理，再用现有「打开方式」回到原软件。已有账号或运行环境问题仍由现有配置和错误处理承接；本轮不声称能解决所有首次使用障碍。

## 2. 首页：选完模板，就知道放什么

继续保留当前顺序：欢迎区 → 大输入框 → 四类快捷入口 → 当前类别的模板卡片。提示只在两个试点模板被选中后出现，位置在输入框顶部；不弹向导、不跳页，也不增加必填表单。

| 模板 | 卡片描述 | 输入框顶部提示 | 空草稿填入的短请求 |
|---|---|---|---|
| 周报生成 | 工作要点或记录文件 → Word 周报 | 粘贴本周要点，或放入记录文件 | 根据这些材料生成本周周报，包含工作进展、问题和下周计划。缺少的信息请标出。 |
| 多表合并整理 | 多份表格或多个工作表 → 汇总 Excel | 放入待合并的表格，可补充合并要求 | 合并这些表格，标注数据来源，并列出字段不一致和疑似重复项。请输出新的 Excel 文件。 |

两个提示共用「添加材料」按钮，直接复用现有文件选择器。拖入文件、附件标签和粘贴继续按当前方式工作；周报可以只粘贴文字，多表合并可以是一份包含多个工作表的文件。

具体规则：

1. **已有内容先保留。** 空草稿或仍未修改的模板文案可填入/替换短请求；用户已编辑的正文、已有附件均不覆盖。已有正文时只展示模板提示，模板要求作为可见说明由用户确认或补充，不暗中改写原请求。
2. **材料提示始终简短。** 加入文件后显示当前附件，提示仍说明可补充什么；「已添加」只代表接收到了文件，不显示「已识别」「校验通过」。
3. **提示可以关闭。** 关闭仅取消当前提示状态，保留正文和附件；发送任务后按现有输入框清理逻辑复位。
4. **发送保持原有行为。** 不加一次模型预检，不引入最低文件数或字数硬门槛，不因用户想先询问如何处理而阻止发送；材料缺失、文件打不开和字段歧义由原会话明确追问。不要仅凭没有附件标签断言没有材料。
5. **合并默认不删除疑似重复。** 原模板直接要求去重，容易把需要保留的记录删掉。本轮把这句改为标记疑似重复、保留来源；只有用户明确给出规则时才执行去重。不确定字段对应关系时询问，不自动猜测。

## 3. 文件卡片：点一下，就能接着改

文件卡片继续采用当前横向布局：文件图标、文件名、类型、打开方式。本次在操作区域增加次要按钮「继续修改」，不改变点击文件名的预览行为。窄窗口下操作换行，文字按钮不依赖悬浮才出现。

交互顺序：

1. 用户点击「本周工作周报.docx」右侧的「继续修改」。
2. 原会话输入框聚焦，顶部出现可移除引用：「正在修改 · 本周工作周报.docx」。文件通过其真实路径和 artifact ID 绑定，不仅使用文件名或最近一次输出。
3. 空输入框展示占位提示：「告诉我哪里要改，例如：把下周计划压缩成三条。」已有草稿原样保留，不自动发送。
4. 用户输入「把下周计划改成三条，其他章节保持不变」并发送；继续调用当前会话和现有 Agent。发送时明确带入选中的文件和用户要求，并请求输出一个新文件、保留源文件。
5. 新文件实际生成后，按现有消息顺序展示新的文件卡片，原卡片仍留在原消息中。没有文件产物就不显示新卡片，也不宣称修改已完成。

边界规则：

- 首发只对当前会话生成、带本地文件路径的 DOCX/XLSX 提供动作。网页、小工具、图片、纯代码块和无本地路径的产物继续现有交互。
- 点击哪份就引用哪份；即使会话里有同名文件，也使用实际文件标识。发送前按现有附件读取链路验证路径可访问；不存在时保留草稿并提示重新选择，不静默改用其他文件。
- 点击另一份文件只更换引用，不清空修改要求；移除引用恢复普通续聊。流式运行中按现有规则禁用发送，不开出并行修改任务。
- 「只改指定部分」「另存新文件」首先是明确的执行要求。本轮没有新增确定性的内容保护、版本回滚或格式保真机制，因此界面不显示「原文完整保留」「无损修改」「检查通过」等保证。是否满足要求必须在真实文件验收中检查。

## 4. 如何嵌入每天的工作

**每周写周报：** 从当前文档复制工作要点 → 选择现有「周报生成」→ 粘贴并发送 → 用「打开方式」在 Word 查看 → 要压缩或补充时点击「继续修改」。用户无需先整理提示词，也无需搬迁日常文档。

**汇总业务表格：** 从原系统导出 Excel → 选择现有「多表合并整理」→ 一次拖入文件并发送 → 打开合并结果继续工作。需要更换统计口径时，对结果点「继续修改」。

**下次处理同类材料：** 从已有任务历史返回，放入新材料，说明「按上次格式处理本周材料，仅使用本次数据」。现阶段沿用对话续接；不包装为已固化、跨周期稳定的流程。新旧数据容易混淆的任务可以直接重新用模板开始。

## 5. 为什么先做这两处

最新研究的 8,082 条可分析外部候选中，1,132 条带文件/文件夹线索，726 条有明确修改诉求。两者支持优先改善交材料和继续修改，但均是可重叠的样本文本信号，不是总体功能使用率。已有模板和文件卡片已经覆盖两处入口，适合低成本验证。

周报与多表合并是基于现有产品能力和可验证性选择的试点，不是报告已经证明的「最受欢迎的两个功能」。保持其他入口原位，避免根据不完整分类重新定位整个产品。

## 6. 研发落点与验收

以本地源码 7592cd034a7c 为基线。下表是实现建议，未执行改动。

| 改动点 | 现有位置与实现范围 |
|---|---|
| 模板描述、短请求、材料提示 | public/quick-actions-i18n.json、src/renderer/types/quickAction.ts 及现有配置加载层；只为两个模板增加可选提示，zh/en 同步 |
| 输入框提示与草稿保护 | CoworkView.tsx 的模板回调与 CoworkPromptInput.tsx；局部状态、复用现有附件选择器，不新增数据库表 |
| 引用文件继续修改 | ArtifactPreviewCard.tsx 增加可选回调，由会话消息层传至当前会话输入框；沿用附件与提交链路，不在通用文件卡片里直接启动任务 |
| 文案与可访问性 | renderer i18n、按钮键盘操作、引用可移除、窄窗口换行；皮肤使用现有产品 token |

两项可以分别灰度，先让模板指引上线，再验证续改入口。原来的结构化任务准备页、连接恢复中心和流程保存方案不属于前置依赖。不在没有研发评估的情况下承诺具体人天。

上线验收集中在以下任务：

- 周报：粘贴要点和添加记录文件均能开始；未知数据不编造；产物实际可用 Word 打开。
- 表格：两文件合并与单文件多工作表均可处理；保留来源；疑似重复不默认删除；实际 Excel 行数与汇总符合约定。
- 草稿：已有文字、附件在切模板、关闭提示和点击续改时不丢失；关闭引用不会发送消息。
- 修改：两份同名文件、选择较早产物、文件移动/删除、正在运行等情形行为明确；生成物确实引用选中文件。手工核查未要求修改的章节、历史数据和源文件，不能以模型自述代替验收。
- 回归：普通聊天、非试点模板、原有预览和打开方式仍可用；macOS/Windows 文件路径处理一致，320px 到桌面宽度无操作遮挡。

若真实文件验收仍发现严重误改，先修对应读写或任务提示，再扩大续改入口。入口按钮本身不会解决全部可靠性问题。

## 7. 最小验证方式

先用少量真实任务走查，观察用户是否还会问「要给它什么」「改的是哪一份」。再给两个试点模板做账号固定分组的小流量验证；两项改动分开开关，以区分效果。

- 主指标：试点模板点击后 10 分钟内，对应任务实际提交的比例；按稳定登录账号每人每模板首个点击机会计数，分母包含点击后没有发送的人。该指标衡量开始门槛，不叫激活率。
- 续改指标：展示过可续改文件卡片的任务中，24 小时内发出引用该文件的修改请求的比例；以会话/任务去重，排除尚未满观察期的样本。它衡量入口使用，不叫修改成功率。
- 结果护栏：对真实 DOCX/XLSX 做人工打开、内容核对和源文件保留检查；记录任务完成时长和用户返工，避免按钮点击增加但结果变差。是否有统计改善以样本量和区间判断，不预设没有基线的增长数字。

现有 templateID、source、artifactType/fileExtension 等字段先核对是否能完整查询和关联；缺少点击尝试与 task/session 的关联时，最小补齐关联标识。续改仅补动作与文件类型等元数据，不上报原文、文件名或文件路径。标识不可靠时不拼接虚假漏斗。
