## 1. 产品决策

将现有通用 Agent 包装成用户能直接理解的工作动作。用户可以选择想得到的结果，也可以直接交材料；系统接着完成输入检查、执行、成品检查、局部修改和再次复用。

第一轮把“材料变汇报”和“多表核对”做成完整流程。二者共用材料接收、运行状态、作品版本和检查记录。“做个小工具”保留现有入口，随后补齐运行验收；截图转 Excel 保留为可选样例，不独占首页和研发资源。

贯穿三次使用：

1. 第一次：今天手上的工作，能在不知道提示词、技能和模型名的情况下开始。
2. 第二次：在刚才的成品上只改指定内容，原来做对的部分保留下来。
3. 下次：换一份材料，沿用确认过的规则和交付格式。

“简单”以到达可用结果所需的准备、等待和返工衡量。少打字、少点击是手段；遇到影响正确性的歧义，仍要让用户作必要决定。

## 2. 证据与设计假设

研究来源：[LobsterAI 用户需求分类与产品固化建议](/tmp/codex-remote-attachments/01a071b6-f317-78c2-9ed5-4abcd1b99e8b/32C7928A-5F70-4829-89AC-2541FAC1C8B3/1-LobsterAI-用户需求分类与产品固化建议.md)。

研究窗口：2026-08-05 21:51:04 至 2026-09-05 21:51:04，不含结束，UTC+8。10,000 条输入候选中，可分析外部候选 8,082 条；获得初步需求标签的外部输入 3,524 条，覆盖率 43.6%。采样经过用户与日期均衡，无全量权重，摘要可能截断；下列数量只作设计线索，不能当作全量用户偏好、成功率、付费贡献或真实需求人数。

| 报告中的观察 | 对设计的影响 | 尚需验证 |
|---|---|---|
| 通用办公、数据表格、财务核算合计 668 条，占已识别外部输入 19.0% | 前两个流程共用文件读写、数字检查与可编辑交付 | 哪个细分更容易首次采用、长期复用 |
| 文件/文件夹线索 1,132 条，分母为 8,082 条外部候选 | 文件选择、拖入、粘贴、输入引用成为统一入口 | 附件-only 输入造成的漏计，不以 14.0% 作为总体渗透率 |
| 明确修改信号 726 条，同一候选分母 | 续改与版本绑定纳入首发验收 | 正常迭代和纠错返工的比例 |
| 环境与 AI 接入合计 735 条，占已识别外部输入 20.9% | 任务内就地诊断、保留材料、修好后继续 | 主动电脑维护与产品使用障碍的占比 |
| 开发 481 条，是明显的单类需求 | 保留小工具入口及现有通用工作区 | 是否实际运行、再次打开，以及维护成本 |
| 显式定时/重复 129 条，显式复用/模板 109 条，可重叠 | 成功后允许保存规则，定时是后续可选动作 | 不能用剔除了自动执行的样本估算自动化总规模 |

三项假设分别验证：明确结果入口降低开始难度；准确续改提高成品采用；带规则的再次运行降低后续成本。入口、交付可靠性和复用能力不可只用一次模板点击实验共同归因。

## 3. 人群与首发范围

优先访谈和灰度的是“今天已有具体材料要处理”的外部用户，尤其运营、销售支持、行政及承担汇报的人。职业仅用于招募覆盖，不作为开机必填问卷。

| 版本 | 明确交付 | 范围边界 |
|---|---|---|
| R1a | 多表核对的完整流程；统一完成卡、检查记录、版本和保护范围；任务内接入恢复 | 首发 XLSX/CSV，支持选择数据表、关联字段、日期范围；金额/数量核对使用确定性计算；复杂宏、外部链接公式、加密文件明确提示不支持 |
| R1b | 材料变汇报；与 R1a 共用交付和续改能力 | 先做可编辑 DOCX 汇报；支持受控模板及可验证的用户模板范围。PPT 在具备渲染检查、缺页/溢出检查后加入；不承诺任意复杂版式精确保留 |
| R2 | 我的流程手动复跑；托盘/快捷键入口小范围验证 | 不做全电脑监听，不要求事先连邮箱/OA，不新建工作流编排引擎 |
| R3 | 已验证流程的周期执行、结果投递；小工具交付增强 | 周期执行须绑定稳定数据源并试跑；小工具按平台分别验收；没有已验证产物检查器的类别保留通用模式 |

R1a/R1b 先后可以根据真实任务基线调整，但不要同时开发全部文档格式与所有系统入口。现有聊天、代码、媒体、研究能力继续可达；新版只是增加低门槛入口。

## 4. 信息架构

沿用现有任务与作品体系，第一版不更换全局导航、不新增并行作品库。

| 位置 | 设计 | 说明 |
|---|---|---|
| 新建任务首页 | 三个结果入口：材料变汇报、多表核对、做个小工具；通用输入保留 | 前两个进入结构化准备页；小工具在交付增强上线前进入既有通用任务 |
| 同一首页 | 一块可拖文件/粘贴内容的输入区 | 有材料时最多推荐三个相关动作；无把握时先让用户选结果 |
| 首页下方 | 最近成品，含待确认、可用、处理中状态 | 用户回来先找正在做的事；不展示无法解释的“效率分数” |
| 任务详情 | 左侧交流与任务状态，右侧当前作品 | 修改绑定正在看的作品和版本；聊天用于补充要求和例外 |
| 作品库 | 同一作品按版本聚合，默认打开最新可用版 | 待检查的新版本有明确标识，避免失败草稿覆盖可用版 |
| R2 首页常用区 | 我的流程，最多展示三个最近使用项，另有全部列表 | 首次保存后出现；R1 不为一个尚未使用的能力增加主导航 |
| 设置/连接管理 | 统一连接状态与最近检测结果 | 技术配置保留在高级区域；任务内出现相关故障时深链到准确位置 |

对新用户：结果入口在前，展示明确输入和输出。对回访用户：最近工作和我的流程在前。默认不以登录年龄猜测职业，不根据一次操作永久改变布局；在“新建任务”页保留完整入口。

## 5. 首次打开与开始任务

### 5.1 首页文案和动作

主文案：“把手头这一步，交给龙虾。”

副文案：“放入文件、粘贴内容，或者选一件要完成的事。”

三个动作必须写结果而非技术能力：

- 材料变汇报：已有资料 + 可选模板 → 一份可以继续修改的汇报。
- 多表核对：本期数据 + 对照表 → 核对结果、未匹配项和差异清单。
- 做个小工具：说明用途 → 可运行预览；可选导出方式在运行平台明确后展示。

“用示例试一下”始终可见，展示真实样例的处理前后；示例任务与真实任务分开统计。不要先发一段介绍 Agent、Skill、MCP 的欢迎长文，也不强迫用户学习教程才能使用。

### 5.2 两条进入路径共用同一张任务卡

路径 A：选择结果 → 放入材料 → 只确认缺失项 → 开始。

路径 B：拖入/粘贴材料 → 推荐相关结果 → 只确认缺失项 → 开始。

材料类型只用于初步候选，不直接推断业务。两张表可能需要合并，也可能需要核对；不能自动决定。内容读取限于用户交入或已授权的材料，不因经过文件夹就递归扫描整个磁盘。

### 5.3 准备页

首屏只显示：材料、预期结果、保护范围、主按钮。系统能可靠推导的信息先填好，并允许修改；关键信息有歧义才展开问题。

| 区域 | 内容及行为 |
|---|---|
| 材料 | 文件名称、角色和读取状态；附件可删除/替换；大文件显示解析中，不伪装成已读取 |
| 结果 | 格式、名称与本地保存位置；首次默认应用管理的任务输出目录，可改为用户选择的目录 |
| 保护范围 | 用一句话说明：例如“仅处理 9 月，8 月及以前保持原样”；可展开具体表页/列/章节 |
| 必要问题 | 一次集中展示影响正确性的缺项，例如核对字段；不为凑“一问”省掉必要澄清 |
| 高级设置 | 沿用已选模型、Agent、运行位置；为新手隐藏非必要选择，现有用户自定义配置不被强改 |
| 主按钮 | “开始核对”或“生成汇报”；没有有效材料时给具体原因，不默默禁用 |

模型策略：沿用用户已配置且可用的模型；套餐新用户用产品推荐默认。质量不够或能力不支持时提供解释与选择；切换成本显著增加时先提示，不暗中换昂贵模型。不把“隐藏模型选择”作为取消用户选择权。

登录/额度：浏览入口和样例说明无需先学配置；真实执行前集中检查认证、额度与所需连接。不弹多轮阻断；保留草稿，登录或补充额度后回到原卡。示例是否免费由成本评估决定，本文不预设赠送政策。

## 6. 任务包 A：多表核对

### 6.1 一条具体使用故事

用户每月拿到不同团队的销售表，需要按公司关联负责人，将当月数据补进汇总表，找出未匹配记录，并保持历史月份内容不变。

首次输入：本月销售表、负责人对照表、已有汇总表。系统识别候选列后显示：“按公司名称关联；本期为 9 月；8 月及以前保持原样。”只有存在多个合理关联键或重复键时要求用户确认。

默认结果：新版本汇总表 + 未匹配/重复键/金额差异清单。原文件不覆盖；用户选择明确覆盖动作时再按受控写入处理。

### 6.2 输入协议

| 字段 | 必需性 | 规则 |
|---|---|---|
| 本期数据 | 必需 | XLSX/CSV；多 Sheet 时选表，不能猜选隐藏 Sheet |
| 对照或历史文件 | 按任务需要 | 标明角色：负责人映射、历史汇总、目标模板 |
| 处理目标 | 必需，有候选默认 | 补当期、核对差异、合并汇总各自使用独立规则；不混为同一动作 |
| 关联字段 | 核对任务必需 | 可确认推荐；重复键不可静默去重，多对多关系需明确处理 |
| 时间/数据范围 | 涉及增量时必需 | 在结果卡显式显示；历史区域加入保护规则 |
| 格式与位置 | 有默认 | 输出 XLSX，保留源文件引用；不使用聊天推断出的任意路径写入 |

### 6.3 检查与验收

- 结构：文件可被独立解析器打开；表页、列、数据类型符合约定。
- 数量：输入/输出行数及排除原因可解释；合并、汇总后的行数变化不直接判失败。
- 数值：总额、分组汇总、舍入规则使用代码检查；识别结果无法确认的数值不自动“修正”。
- 关系：未匹配、重复键、一对多项单列；匹配不完整时不宣称全部正确。
- 保护：历史区域的值、公式和约定格式与基线比较；保护违规是阻断交付的检查失败。
- 公式：写入公式与实际计算结果分开检查。没有相应 Office/LibreOffice 计算能力时，不能把缓存值当成已重算；显示未验证并按任务要求决定是否阻断。
- 文档内宏和外部链接不得作为默认执行步骤。对不支持的格式给明确替代输入，不声称已完整保留。

未匹配项本身可以是正常业务异常。检查器保证它被准确列出，用户可以确认保留在异常清单；不得用“用户采用”覆盖保护违规或文件损坏。

## 7. 任务包 B：材料变汇报

### 7.1 输入与流程

用户交入工作记录、表格、旧汇报或模板，选择“周报/项目汇报/自定义”。默认先生成可编辑 DOCX；PPT 在版式检查能力满足后可选。

有模板时，系统展示必含章节和保护章节；无模板时，用清晰的轻模板，并允许用户改目录。受众或周期会改变结构时才询问，不能自行补出不存在的业绩、预算和结论。

材料读取 → 内容映射/缺失项 → 生成 → 独立检查 → 成品。简短且无歧义的任务直接生成；内容结构复杂或涉及删减时先给目录确认，避免每个简单任务都变成长规划流程。

### 7.2 固定规则

- 每个关键数字可回溯到材料及位置；冲突来源先指出差异，不任选一个。
- 缺失数据以待补标识保留，不用虚构数据填满报告。
- 用户要求保留的章节/页/图表需明确绑定。输入无法稳定定位保护范围时，先请用户选择范围或降级为建议修改。
- 修订需说明新增、替换和删除；目标之外的章节保留。
- DOCX 检查可打开、必含章节、关键数字与页级渲染；不承诺仅靠文件成功写出即可保证视觉正确。
- PPT 检查页数、缺页、内容越界、文字溢出及引用。没有渲染检查时不标注“版式已检查”。

示例续改：“把第三节写短一点，数据和其他章节保持原样。”产品应锁定当前第三节和基线版本，只展示这次改动，不另起一个无关文件。

## 8. 成品、局部修改与版本

### 8.1 完成卡

第一行：成品名称 + 当前版本 + 状态。

第二行：本次实际完成的工作，最多两行；避免一大段“已完成”的自述。

检查区：逐项显示通过、未通过、待用户确认、未执行/不可验证。每项记录检查对象、工具结果和时间；“模型说检查过”不能替代检查证据。

操作：打开成品、继续修改、查看变化、保存到指定位置；“可以用了”是独立反馈。保存/打开不自动计为采用，也不需要确认采用才能取走文件。

作品状态与运行状态分开：运行结束可能只得到待核对草稿。界面显示“已生成，1 项待核对”，不能同时给出没有限定的“全部完成”。

### 8.2 续改面板

固定顶部：“正在修改：作品名 · V2”。范围由用户当前看的版本和所选部分决定，不能从聊天里猜“刚才那个”。

默认保护未选区域；用户改动要求与保护规则冲突时先解释冲突。用户可以选择扩大范围，但新范围要可见。

修改在临时工作副本执行。检查通过后登记新版本、生成差异摘要、更新作品的最新可用版本；失败时保留现有可用版本和失败草稿，给恢复入口。

外部修改检查：执行前记录内容指纹，写回/登记前重查；若用户在 Office 中改过原文件，提示“文件已更新，需重新读取”，不能直接覆盖。

### 8.3 版本规则

- 作品有稳定 ID；版本有独立 ID、父版本、输入快照引用、修改范围、检查记录和文件位置。
- 正在查看的版本、最新生成版本、最新可用版本是三个不同指针。
- 选择旧版本只是查看，不改变当前版本。恢复旧内容会产生新版本，保留恢复前内容。
- 应用内产物的缓存刷新计数不能直接当作业务修订版本。
- 版本保存有本地存储成本；显示占用并允许删除旧版本。用户固定的模板和仍被流程引用的版本，删除前展示影响。
- R1 限定支持的结构化保护范围；无法验证任意版式/任意二进制内容时，要明确范围限制。

## 9. 接入和环境：在原任务中解决

预检只检查当前动作实际需要的能力。处理本地表格不要求用户先连浏览器、IM 和邮箱。

| 状态 | 用户可见内容 | 下一步 |
|---|---|---|
| 未配置 | “此任务需要可用模型” | 显示套餐默认或已有可用配置，保留材料 |
| 待授权 | “需要访问你选中的文件夹” | 选择目录/完成授权，范围明确 |
| 可用 | 最近一次实际检测通过 | 正常执行，不弹打扰 |
| 失败 | 具体原因及可执行动作 | 就地检测、配置深链或换用已有连接 |
| 暂时不可用 | 服务/网络暂时失败 | 可重试的读步骤有限重试，恢复后继续原任务 |
| 有工作正在运行 | 修复会影响其他任务 | 显示相关运行，待其结束再修复；不强杀共享网关 |

诊断可以检查已有配置和连接；覆盖配置、安装依赖、删除文件等动作显示具体影响，并沿用现有授权规则。绝不把运行时配置修复扩大成静默重装整个环境。

恢复后必须重新做最小调用测试，再恢复到原任务的安全步骤；材料、已确认字段和保护范围不丢失。导出、覆盖、发送等有副作用的步骤不能因重试自动重复执行。

“我要清理 C 盘”属于用户主动任务，与“为了做表格被迫装依赖”分开记录和设计。前者需要候选清单和恢复策略，不能计为产品配置失败。

## 10. 工作流耦合：先手动复用，再自动运行

### 10.1 保存为我的流程

用户认可结果后出现非阻断入口：“下次也这样做”。首次只让用户确认流程名称、每次替换的材料和要保留的规则。

保存内容：输入角色与字段要求、固定模板的版本引用、可变参数、保护规则、检查规则、输出规格、目标位置、所需能力。身份凭证留在现有安全存储，流程只引用连接 ID。

不把整段历史聊天作为执行规范；归纳出的规则要让用户看见，尤其文件范围、数据关联、删除/覆盖规则。默认每次由用户选新材料，不后台扫描目录。

保存过程不自动创建定时任务，不因点击“可以用了”自动收藏或打开通知。

### 10.2 再次使用

点“我的月度核对” → 放入本月文件 → 显示沿用规则及本次参数 → 开始。

新文件列名或表页变化时，指出变化并让用户重新确认映射。不能偷偷套用旧字段，也不让用户重填全部设置。

流程与一次运行分开：修改本次参数默认只影响本次；选择“以后也这样”才生成流程新版本。旧运行继续引用旧版本，方便追查。

### 10.3 桌面轻入口

R2 在已验证流程上增加可选托盘/快捷键入口：用户主动调用后，粘贴内容或拖入文件，选择一个结果或已保存流程。

不预设具体快捷键；按平台检测冲突后让用户启用。第一版无需剪贴板常驻监听、屏幕录制或全系统辅助功能权限。文件右键、macOS Services 等另做平台小实验，不能将其视为现有能力。

轻入口只承担材料接收、动作选择和状态回执，复杂修改打开已有主窗口。结果仍归属同一个任务和作品，避免第二套历史记录。

### 10.4 定时运行与投递

仅对已成功手动运行的流程提供“按时运行”。用户需确认：可自动读取的数据源、运行时间/时区、输出位置、是否投递及目标。

每次手动上传的输入槽不能直接开自动运行；必须绑定稳定数据源并试跑。仅引用上次文件，不能宣称已读取本周新数据。

调度沿用现有 OpenClaw cron。电脑关机、离线、睡眠或应用未运行时，不承诺本机按时执行；界面展示执行设备与条件。是否补跑由任务策略明确决定，防止恢复后连续发送多份过期结果。

触发、处理、检查、投递分别有状态。处理成功但检查失败不自动投递；投递失败保留合格产物，重试仅针对投递，并使用去重标识。IM 中的“继续修改”须回到同一作品版本，并核验发送者/会话权限，不能只依据桌面账号埋点身份授权。

## 11. 产品状态与异常合同

| 状态 | 主文案 | 可执行操作 | 转移条件 |
|---|---|---|---|
| 准备中 | “放入本期数据” | 选材料、改规则、取消 | 必需材料齐全 |
| 需确认 | “有两列可能作为关联字段” | 确认映射、返回 | 用户消除影响正确性的歧义 |
| 需处理连接 | “模型连接失败，材料已保留” | 检测/修复、更换已有连接 | 最小测试通过 |

| 检查中 | “正在检查历史数据是否改变” | 查看检查项、停止 | 检查执行结束 |
| 待核对 | “已生成，1 项需要你确认” | 看异常、继续修改、取走草稿 | 用户确认允许的业务异常，且必过项通过 |

## 14. 验证计划与发布门槛

### 14.1 三类验证分开做

1. 可用性：建议先找 12–18 位目标外部用户，覆盖未激活新人、曾放弃的人和有重复工作的人；这是发现问题的建议规模，不用于证明市场占比。让用户带获授权的真实材料，不讲解，观察能否选择正确动作并拿回原工作使用。
2. 质量：为每个首发格式建立固定匿名验收集，包含缺材料、重复键、格式差异、保护区域、公式、外部改动、模型故障等。检查器的结果要能人工复核；不只测试生成了文件。
3. 效果：先限定版本和合格用户，再随机分组。先测任务入口，随后单独测轻入口；避免把多个改变全部捆绑后归因于 Widget。

### 14.2 指标合同

| 指标 | 分子 / 分母 | 窗口与边界 |
|---|---|---|
| 首次真实交付率 | 24 小时内至少一次真实输入产物通过必需检查的用户 / 随机分组的全部合格首次体验用户 | 从入组起 24 小时；只统计观察满 24 小时的人，未提交者留在分母；样例不计入 |
| 首次采用率 | 24 小时内明确反馈至少一个真实成品可用的用户 / 同一入组人群 | 未反馈记未知并保留在整体分母；另报反馈覆盖率，不当作全部不满意 |
| 交付质量 | 通过该类型必需检查的产物 / 尝试交付的产物 | 按格式、任务包、模型、版本拆分；尚在执行的单列 |
| 保护约束违规 | 发生保护违规的任务 / 含保护规则且已完成检查的任务 | 确认的违规列为发布阻断；没有观察到违规不等于真实概率为零 |
| 成品采用反馈 | 明确采用的任务 / 已交付任务；另报采用 / 有明确反馈任务 | 两个分母同时展示，避免只看愿意反馈的人 |
| 续改质量 | 目标范围检查通过且保护范围不变的修订 / 已完成检查的修订 | 正常创作修改和修复错误分开；有修改次数不直接当质量差 |
| 首个可用结果耗时 | 入组→可用结果，另拆材料准备、排队、执行、检查耗时 | 报中位数和 P90，并报超时/未完成比例；不只报告成功者平均值 |
| 再次工作 | 入组后第 2–7 天完成另一件真实任务的用户 / 观察满 7 天的入组用户 | 第 2–7 天按入组后 [24h,168h) 定义，自动系统步骤和示例不计；另报首次采用者条件复用率 |
| 周期工作复用 | 在两个预期业务周期内成功完成下一期的用户 / 观察满两个周期的适用用户 | 每周流程看至少 14 天，每月按两次实际到期点；不能统一用 D7 淘汰低频工作 |
| 接入恢复 | 修好后继续原业务任务并交付的用户 / 遇到该类接入障碍的用户 | 连接成功仅为中间指标；产品障碍与主动电脑维护分开 |
| 成本 | 试验组所有相关模型、工具、重试和检查成本 / 被明确采用的成品数 | 包含失败尝试；分母为零不展示虚假的 0 元成本；本地耗时另列 |

曝光点击和“零提示词完成”用于诊断交互，不作为最终成功标准。用户在样例上点“可以用了”不能进入真实采用指标。

### 14.3 发布决策

- 先记录基线，再由产品、研发、数据确定最小有意义改善幅度和所需样本量；当前研究无法给出可信的转化提升目标。
- 必过质量条件：固定验收集内无已知保护违规、无静默覆盖、无重复外发；支持范围内文件可打开，所有宣称执行的检查有证据。
- 灰度期间一旦发现保护违规或重复外发，停用受影响路径并保留通用功能；不能为了转化提升接受数据损坏。
- 按版本/渠道/新老用户分层观察；不把现有重度用户的高复用当作新人激活成功。
- 配置化开关分别控制任务入口、作品版本、手动流程与桌面入口；回滚不得删除已产生的作品或用户保存的规则。

## 15. 实施前需要团队定下的具体边界

1. 首发核对的业务小场景与格式范围：本方案推荐“当期更新 + 负责人/实体关联 + 历史保护”，需以真实验收样本确认。
2. DOCX 用户模板支持范围及不支持时的降级文案；不要默认所有模板可无损修改。
3. 模型默认策略、样例运行成本和额度提示；不根据当前需求计数推出收费政策。
4. 本地版本保留策略、存储位置，以及哪些受保护区域可以可靠检查。
5. 桌面入口先在哪个平台灰度；有冲突时的快捷键策略。

这些决定不阻碍原型评审和质量基线建立。评审时优先走完“导入材料—核对—只改本期—确认成品—保存规则—换材料复跑”，并专门走一次“连接失败—就地恢复—原任务继续”。
